## Key Decisions

- **Ownership:** Validator measures its reviews; Runner adds workflow/run/step/execution-session context and consolidates; Evals evaluates and prices. Runner-driven evaluations do not independently count Validator snapshots.
- **CLI boundary, not private files:** Launch `run`/`check`/`review` with `--metrics-consumer agent-runner --metrics-context <opaque-id>`. Durably save the ID's original workflow/execution-session/parent-attempt mapping before launch. Use `metrics capabilities`, `metrics export`, and `metrics acknowledge` afterward, including on failure and during recovery. Scoped data commands select `--project`, optional `--config`, `--consumer`, `--context`, and `--protocol-version`; export declares its supported set through repeatable `--measurement-version` and optionally bounds `--max-records`; acknowledgment supplies `--receipt`. Read-only `metrics pending` discovers contexts without knowing their IDs, with optional consumer filtering and bounded inventory pages. Validator resolves storage without validating review definitions. See the exact command forms and JSON fields in `design.md`. No private-path ingestion or parallel JSONL transport.
- **Receipt acknowledgment:** Export is non-consuming and returns an opaque receipt for the exact consumer/context and record revisions exported. Runner durably incorporates the batch before calling Validator's acknowledgment CLI. An older receipt cannot release a newer completion update. Repeated acknowledgment is harmless; failed persistence or invalid receipts must not release pending evidence. Stable record/revision identities support deduplication if Runner crashes after saving but before acknowledging.
- **Bounded delivery:** Export returns a bounded batch in stable pending commit order with `batch.generation`, returned/remaining revision counts, and `scope_complete` as of that generation. Save/ack each batch and repeat export to drain the scope. Export alone never advances a hidden cursor. Finalization and associated attempts may arrive in separate batches: reconcile imported heads, original membership, batch coverage, and gaps before claiming complete delivery. No future completion is implied by a currently drained scope. Operators discard only explicitly previewed batches, never a receipt-free whole-context purge.
- **Overlapping receipts:** A revision's durable disposition through any valid receipt releases payload pins from all overlapping receipts; a newer export alone releases nothing. Small manifests/dispositions remain for idempotence even after payload reclamation. R1 covering revision 1 cannot indefinitely pin it after R2 covering 1+2 is acknowledged. Runner must not require a separately acknowledged abandoned R1 to complete recovery.
- **Common measurement semantics:** Runner's own adapters and nested measurements use a common versioned vocabulary. Outer workflow and Validator artifacts may differ. Preserve the full accounting/attribution payload rather than translate it into a lossy lowest common denominator.
- **Identity:** Keep requested, resolved launch, and observed effective identities distinct. Resolution is not evidence that a provider used the requested model. Keep Validator session, command invocation, model attempt, Runner execution session, parent step attempt, and provider CLI session identities separate.
- **Tokens:** Preserve canonical `input_total`, `input_uncached`, `cache_read`, `cache_write`, `output`, `reasoning`, and `provider_total`, including availability, inclusion relationships, derivation, and precision. No grand total without established non-overlapping components. Unknown is not zero.
- **Multiple models:** One dispatch remains one measured attempt. Preserve provider-supported per-model allocations and attempt-level unallocated usage with independent attribution completeness. Never fabricate allocations or count allocation rows again as attempts.
- **Allocation/cost joins:** Preserve attempt-local stable `allocation_id`, observed `identity_id` and available/unavailable identity references, and `provider_reported_costs[]` entries with `cost_evidence_id`, amount/currency availability, scope, allocation reference, coverage, precision, and overlap. References resolve within the selected complete attempt revision and remain stable for the same evidence across updates. Do not promote an allocation cost or a partial running subtotal to complete attempt cost.
- **Versions:** Preserve producer version/build provenance, adapter/parser-mapping version, CLI version or unavailability, and source format/event version or unavailability.
- **Recovery:** Accept attempt lifecycle evidence and invocation finalization with the expected attempt set and collection state. Confirmed zero dispatch is not a missing-metrics gap. Updates/replay must count one original attempt once and retain the original workflow attribution; new dispatches are new attempts. Unrecoverable evidence remains explicitly incomplete.
- **Failure isolation:** Validator warns on publication failures without changing validation outcomes. Local snapshot and handoff availability are independent. Partial valid records remain usable without claiming complete delivery.
- **Pending delivery retention:** The user approved preserving pending telemetry across ordinary cleanup and historical rotation, including `max_previous_logs: 0`, until Runner acknowledges durable receipt or the user explicitly discards it. Successful export alone is not acknowledgment. Pending data can accumulate during broken delivery; silent eviction is not allowed. Explicit discard leaves a delivery gap, not successful receipt. Storage failure still warns and degrades history rather than blocking validation. This does not protect against external directory deletion or disk loss.
- **Aggregation:** Measurements are authoritative; aggregates are deterministic views with per-field state, known subtotal, fidelity, and coverage. Parent usage excludes child usage. Nested/parallel durations must not inflate workflow elapsed time.
- **Evidence safety and pricing:** Carry only allowlisted model identity/usage/timing/provenance evidence, including provider-reported cost when available. No prompts, responses, credentials, environment values, unrestricted event payloads, or account/user/organization/email/host identifiers, including in diagnostics. Explicitly allowed opaque execution/session IDs remain valid but cannot encode excluded identifiers. Do not price or rewrite measurement evidence in the handoff.
- **Versions and ownership:** Common measurement, Validator artifact, export protocol, and bootstrap capabilities each start at independent version 1. Validator initially owns/distributes language-neutral schemas and fixtures; Runner/Evals pin reviewed versions. This is not a request to reset Runner's workflow artifact version. Reject unsupported protocol/measurement versions explicitly and retain unacknowledged evidence.
- **Mixed measurement versions:** Every immutable invocation/attempt revision carries `measurement_schema_version` within its digest input. Upgrades may leave mixed versions in a session/scope, including newer revisions of the same record. Declare all supported measurement versions; export checks the whole pending scope for incompatibility before issuing a receipt, then reports actual returned `measurement_schema_versions`. Preserve each record's version unchanged. Validator root aggregates use separately declared `aggregate_measurement_schema_version`; Runner must likewise make aggregate interpretation explicit, using reviewed cross-version mappings or reporting coverage limitations. Never choose an older compatible head over the actual latest one or interpret a root maximum version as conversion.
- **Closed schema evolution:** Published telemetry schemas are closed, including nested/source variants. New fields, even optional ones, require a new owning-contract version. Preserve all accepted fields, including known optional fields; reject undeclared fields or unsupported versions without acknowledgment. This supersedes the earlier unknown-field-forwarding fixture/compatibility obligation. Digest validation uses the entire accepted record, not a lossy Runner projection; it does not waive schema validation.
- **Records:** `record_type` is `invocation` or `model_attempt`; `record_id` is the corresponding producer ID; positive integer `revision` and `measurement_schema_version` identify a complete replacement payload and its interpretation. Exports can include initial and terminal revisions together or in separate batches. Never add revisions. Conflicting same-ID/revision payloads are diagnostics. Receipt manifests bind exact record revisions/versions/digests and scope. There is no `context_records` field in v1: use embedded original parent IDs and durably incorporated records; missing required parent evidence remains a gap.
- **Recovery states:** Export distinguishes pending, previously acknowledged, discarded, and missing evidence. Prepared-only records after interruption do not prove a subprocess started or consumed zero. Receipt-scoped `metrics discard ... --confirm` records a durable gap; a later acknowledgment cannot erase that gap. Original configuration/storage relocation is not automatic migration.
- **Approach:** Validator uses immutable JSON revisions, atomic metadata commits, a short telemetry lock separate from the run lock, and recoverable cleanup staging. These are private implementation details, not paths Runner should parse. Preserve honest uncertainty even where the old Runner contract is less expressive.

## Open Questions

The Runner agent's review accepted the architecture and identified two producer-contract gaps. The user approved both resolutions, now written in the design/specs:

- **Delivery during unfinished closure:** Export/acknowledgment operate on intact committed delivery records independently of archive recovery and without the run lock or another validation/clean command. Later closure recovery preserves intervening acknowledgments. Temporary metadata contention is retryable; corrupt committed evidence, incompatible storage, and inaccessible original configuration identify the intervention needed. No additional recovery CLI is introduced.
- **Deterministic digests:** Records carry SHA-256 over RFC 8785 JCS serialization of the complete envelope/payload excluding only top-level `digest`. Runner verifies before transformation/incorporation/acknowledgment. Shared original JSON, canonical bytes, and hashes cover fractional/exponent values, Unicode/escaping, signed zero, and numeric limits. Evals preserves digest/revision without needing to rehash merely to price.

Evals review has also been assessed, and the user approved stable allocation/cost joins and closed schema evolution. These changes are now in the design/specs. Recheck the targeted revisions and fixtures; neither review constitutes unconditional integration signoff.

The user also approved the final approach-review resolutions now reflected here: per-record measurement versions and explicit aggregate interpretation, bounded inventory/export, disposition-based release of overlapping receipt pins, and removal of `context_records`. Producer-specific refinements cover attempt-isolated collection, all cleanup callers including `skip`, configured retention, non-exiting run/check/review outcomes without a new console transport, privacy exclusions, and evidence-backed Codex/Claude input/output as the minimum acceptance bar. Legacy log-based reports are not the new measurement authority. Missing producer evidence remains an acceptance limitation; this approval authorizes no paid captures.

- The written CLI/record contract and schema ownership need this interoperability review; implementation must then produce executable schemas and shared fixture bytes conforming to it. Do not mistake a designed field contract for tested cross-language compatibility.
- Runner owns its durable replay scheduling, workflow artifact migration, and persistence transaction linking launch mappings, imported revisions, and outstanding receipts. No exactly-once transport guarantee has been approved. Runner must be able to invoke the metrics CLI in the original project/configuration environment during recovery.
- Runner-native adapter migration must preserve distinctions between invocation-resolved and telemetry-observed identity without manufacturing new evidence for old runs.

## Approved Companion Obligations

- **Durable ingestion:** Save original attribution before launch, then imported records, verified revisions/digests, and outstanding receipts before acknowledgment. The inspected `internal/stateio/stateio.go` atomic writer does not sync files/directories; atomic replacement alone does not establish this durability boundary. Cover crashes before durable incorporation and after it but before acknowledgment.
- **Outer-artifact migration:** Introduce a workflow artifact version beyond current v3 containing one current measurement head per producer attempt, with selected revision/digest, original attribution, history/delivery completeness, and gaps. Retain the raw accepted producer record separately from Runner attribution fields so its digest remains meaningful. Revisions replace; actual redispatches append. Do not scope producer deduplication to the later recovery parent.
- **Native identity and usage:** Put launch-derived identity in resolved, not observed. Migrate native measurements to the common contract without fabricating unsupported historical evidence or defaulting unknown cache categories to zero.
- **Launch plumbing:** Forward explicit correlation flags through scripts and preserve the actual project/configuration choice. A `metrics_source` declaration alone cannot inject flags into arbitrary shell commands. Retrieval and acknowledgment use the original context even when closure is unfinished.
- **Consumer projection:** Carry scoped cost/usage and unallocated evidence into Evals unchanged in meaning. New closed-schema validation replaces opaque unknown-field preservation; all supported data must still survive.
- **New shared cases:** Pin mixed-version session/scope and aggregate fixtures; bounded multi-batch delivery with invocation/attempt separation; repeated export before disposition; overlapping R1/R2 receipts including both save/ack crash boundaries and re-ack after payload reclamation; supported parent joins without `context_records`; and expanded privacy canaries. Version negotiation and complete delivery must not be inferred from a single root version or terminal marker. These add to INT-003/005 and actual integration acceptance in the Validator test plan.
